hi-c_fastqtocool_hicup_cooler

Overview

This workflow processes paired-end FASTQ reads from Hi-C or Hi-ChIP experiments to generate normalized contact matrices. It utilizes the HiCUP pipeline to truncate reads at religation sites, map mates independently using Bowtie2, and filter for valid, uniquely mapped pairs. The workflow specifically uses the middle of the restriction fragments as coordinates to ensure high-resolution accuracy during the pairing and deduplication stages.

Following initial processing, valid pairs are converted into a sorted, Tabix-indexed format using cooler csort. These pairs are then binned into a matrix at a user-defined resolution and balanced using the Iterative Correction and Eigenvector decomposition (ICE) method via cooler. While designed for Hi-C, the workflow is compatible with Hi-ChIP data by utilizing the raw matrix outputs instead of the balanced values.

The final outputs include a filtered and sorted valid pairs dataset and a visualization of the contact matrix for a specified genomic region generated by pyGenomeTracks. For detailed instructions on input parameters—such as restriction enzyme motifs, genome indices, and bin sizes—refer to the README.md in the Files section.

Ensure your input is organized as a paired-end fastqsanger collection to match the workflow's requirement for automated processing of multiple samples. Key parameters include the specific restriction enzyme cut site (e.g., A^GATCT) and the genome name corresponding to available bowtie2 indices. For downstream analysis at different resolutions, the "valid pairs filtered and sorted" output (juicer_medium_tabix.gz) can be reused in the hic_tabix_to_cool_cooler subworkflow. Refer to the README.md for detailed guidance on biotin fill-in settings and specific coordinate filtering for capture Hi-C. You can use planemo workflow_job_init to generate a job.yml for reproducible execution.

How to run (Planemo)

Local Galaxy (default engine)

planemo run hic-fastq-to-cool-hicup-cooler.ga job.yml --download_outputs --output_directory . --output_json output.json

Optional: --galaxy_root /path/to/galaxy speeds up spinning up a local Galaxy.

Docker Galaxy

Append e.g. --engine docker_galaxy --ignore_dependency_problems (requires Docker).

External Galaxy (usegalaxy.org / EU / …)

planemo run hic-fastq-to-cool-hicup-cooler.ga job.yml --engine external_galaxy --galaxy_url SERVER_URL --galaxy_user_key YOUR_API_KEY

Create a reusable profile: planemo profile_create myprofile --galaxy_url ... --galaxy_user_key ... --engine external_galaxy then planemo run hic-fastq-to-cool-hicup-cooler.ga job.yml --profile myprofile.

Job file

  • Generate a template: planemo workflow_job_init hic-fastq-to-cool-hicup-cooler.ga -o job.yml
  • Lint: planemo workflow_lint hic-fastq-to-cool-hicup-cooler.ga

See Running Galaxy workflows in the Planemo documentation.

Invocation outputs

After a successful run with --download_outputs, files appear under your chosen --output_directory. --output_json records CWL-style metadata for outputs (paths, checksums).

On an external Galaxy, use planemo invocation_download INVOCATION_ID --profile ... to fetch outputs, or track progress with planemo workflow_track INVOCATION_ID.

Workflow steps marked as workflow outputs in the editor are listed under Workflow outputs; exact filenames depend on tools and Galaxy configuration.
